# 防背锅指南｜The Workplace Self-Protection Handbook

> 不怕做事，就怕责任不清。  
> 不怕出问题，就怕没有记录。  
> 不怕承担责任，就怕替未经授权的决策和未经核实的判断承担责任。

《防背锅指南》是一份面向普通职场人的实用风险控制手册，帮助大家在项目协作、跨部门沟通、需求变更、系统上线和故障处理时，明确责任边界、记录关键事实、及时预警风险，并推动问题解决。

本项目借鉴开源指南常见的条目化组织方式，内容为原创整理；不隶属于任何其他指南项目。

## 核心原则

**做事有交付，沟通有记录，风险有预警，决策有来源，责任有边界。**

1. 重要事情，不只靠口头说：关键要求、决策、验收和风险应有适当书面记录。
2. 接任务，先确认交付标准：明确范围、期限、依赖条件和验收人。
3. 不替别人做未经授权的决定：建议可以提出，决策权限必须清楚。
4. 风险提前说：说明事实、影响、建议方案和需要谁确认。
5. 需求变化要同步记录：变更可能影响工期、成本、测试和风险。
6. “收到”不等于“批准”：接收信息、参与讨论和正式授权不是一回事。
7. 发现问题先保护现场：依规保存日志、版本、工单和时间线。
8. 不为赶进度隐瞒风险：如实说明测试状态和未完成事项。
9. 不甩锅，也不替人背锅：按职责协作，按事实复盘。
10. 记录事实，不记录情绪：避免未经证实的指责和猜测。

## 常见场景：可以直接使用的话术

### 口头任务需要确认

> 收到。我先按目前沟通的方案推进。为避免理解偏差，我确认一下：本次交付范围是……，计划完成时间是……，验收由……确认。涉及生产环境变更的部分，将在必要审批完成后执行。如有调整，请及时告知。

### 需求增加但期限不变

> 新增需求会影响开发和测试工作量。若上线时间保持不变，建议在新增功能、原有范围和测试时间之间确定优先级。请确认采用哪种方案，我会据此更新计划。

### 发现风险需要升级

> 当前发现的情况是……，可能影响……。已知依据为……。建议方案是……，需要……在……之前确认。若暂时无法确认，我会按现行流程控制风险并同步进展。

### 故障发生后

> 当前优先恢复业务并控制影响。根据现有记录，故障发生于……，涉及……。根因仍需结合日志和环境验证。建议先完成恢复与影响评估，再根据完整证据开展复盘。

## 项目管理检查清单

- [ ] 任务范围、负责人、执行人和验收人明确
- [ ] 依赖事项、交付时间和风险已记录
- [ ] 需求变更有确认记录，并评估工期与测试影响
- [ ] 关键决策由有权人员确认
- [ ] 上线前完成适用的测试、审批、备份和回滚准备
- [ ] 故障处理保留时间线、日志和恢复验证结果
- [ ] 交接事项、遗留问题和后续负责人明确

## 贡献方式

欢迎通过 Issue 提交建议、补充脱敏案例，或提交 Pull Request。请先阅读 [CONTRIBUTING.md](CONTRIBUTING.md)。

案例必须去除姓名、公司、客户、账号、联系方式、商业秘密和其他敏感信息。请勿提交未经授权获取的内部文件或个人数据。

## 免责声明

本项目提供一般性的职场沟通与管理经验，不构成法律、劳动关系、信息安全或合规方面的专业意见，也不能保证完全避免争议。具体行动应遵守适用法律、公司制度、行业规范和应急流程。不得以留痕为由伪造、篡改或违规传播记录；遇到紧急安全风险，应优先按照正式应急机制处理。
