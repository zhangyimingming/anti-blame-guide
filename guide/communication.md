# 职场沟通与留痕

## 原则

关键事项的记录目的，是准确还原任务、决定和行动，不是制造对立或收集攻击同事的材料。

## 哪些事项值得书面确认

- 任务目标、交付范围、期限和验收标准
- 需求变化及其对工期、成本、质量的影响
- 重要技术或业务决策及其决策人
- 已知风险、风险通知时间和处置建议
- 生产环境变更、审批、测试和恢复安排
- 工作交接、未完成事项和后续责任人

## 五步确认法

1. **复述事实**：简短说明自己理解的任务。
2. **明确范围**：写清包含和不包含的内容。
3. **确认责任**：区分负责人、执行人、配合方和验收人。
4. **指出依赖**：说明需要哪些输入、权限或审批。
5. **留下结论**：在适当的工作系统中记录确认结果。

## 可复用话术

### 任务确认

> 为确保理解一致，我确认本次任务的目标为……，交付范围为……，计划时间为……，验收人是……。当前依赖事项为……。如理解有误，请指出，我将据确认结果推进。

### 会议结论

> 本次会议结论：一、……；二、……。待确认事项：……，由……在……之前确认。行动项及负责人：……。如有遗漏或理解偏差，请在……前补充。

### 风险提示

> 当前已知情况为……，依据是……。可能影响……。建议采取……，需要……确认。若条件未满足，计划和风险将相应调整。

### 任务优先级冲突

> 目前我正在处理 A 和 B，两项任务的截止时间分别为……。若新增 C 需要优先处理，请确认优先级以及 A/B 的时间安排，我会据此调整计划。

## 留痕的边界

- 使用公司认可的邮件、工单、项目管理和审批系统。
- 记录应及时、准确、完整，保留必要上下文。
- 不要无差别抄送大量无关人员。
- 不得伪造、删改或违规复制内部记录。
- 遵守数据分类、隐私保护和保密制度。
- 紧急情况先按应急流程控制风险，再按制度补齐记录。

## 记录质量自检

- 读者能否看懂发生了什么？
- 是否区分事实、推断和建议？
- 是否明确了负责人和截止时间？
- 是否记录了决定及其来源？
- 是否包含不必要的个人或机密信息？
